# 股票交易知识与本项目实现指南

本文面向首次接触股票交易系统的开发者和测试人员，解释本项目使用的核心业务概念、计算规则及实现边界。它描述的是 **Equity Trade Booking Engine 当前实现**，不是投资建议，也不是完整的券商清算或会计系统规范。

## 1. 从交易到盈亏的数据链路

```text
证券账户（Account）
  └─ 成交记录（Trade）
       └─ 按账户和股票代码重放有效成交
            └─ 持仓（Position）
                 + 市场报价（Market Quote）
                      └─ 市值与未实现盈亏（P&L）
                           └─ 估值快照（Valuation Snapshot）
```

- **Account** 是交易的归属账户，只有 `ACTIVE` 账户可以新增成交。
- **Trade** 是系统的事实记录，包含方向、数量、成交价和实际成交时间。
- **Position** 不是独立录入的数据，而是从所有 `BOOKED` 成交实时计算的结果。
- **Market Quote** 提供当前估值价格；MySQL 保存业务事实，Redis 只缓存行情。
- **Valuation Snapshot** 定期保存组合估值，用于展示历史曲线。

## 2. 股票、代码与交易方向

### 2.1 股票代码（Ticker）

Ticker 是证券的交易代码，例如 `AAPL` 或 `BRK.B`。本项目会去除首尾空格、转成大写，并要求代码匹配：

```text
[A-Z][A-Z0-9.-]{0,9}
```

格式正确不代表证券一定存在。下单前还会通过 instrument validator 验证它是否是系统支持的美国股票、ADR 或 ETF。

### 2.2 BUY 与 SELL

- `BUY`：买入股票，增加持仓数量和成本基础。
- `SELL`：卖出股票，减少持仓数量，并按卖出前的加权平均成本减少成本基础。

本项目禁止做空。任一账户、任一股票在时间顺序上的持仓都不能小于零，因此卖出数量不能超过该时点的可用持仓。

## 3. 成交记录（Trade）

一条成交的主要字段如下：

| 字段 | 含义 | 项目规则 |
| --- | --- | --- |
| `accountId` | 证券账户 | 必填，账户必须存在且为 `ACTIVE` |
| `ticker` | 股票代码 | 标准化为大写并验证是否受支持 |
| `side` | 交易方向 | `BUY` 或 `SELL` |
| `quantity` | 成交数量 | 大于 0，最多 6 位小数、13 位整数 |
| `tradePrice` | 每股成交价 | 大于 0，最多 6 位小数、13 位整数 |
| `executedAt` | 实际成交时间 | 不能晚于服务器当前时间 60 秒以上 |
| `createdAt` | 系统记录时间 | 由服务端生成 |
| `status` | 生命周期状态 | `BOOKED` 或 `CANCELLED` |

`executedAt` 和 `createdAt` 不应混淆：前者表达交易在市场中何时成交，后者表达系统何时记录该操作。补录历史成交时，两者可能明显不同。

### 3.1 成交排序

计算持仓时，系统只重放 `BOOKED` 成交，并按以下顺序排序：

1. `executedAt`
2. `createdAt`
3. Trade UUID

稳定排序非常重要。例如先卖后买即使最终净数量为正，中间仍会出现负持仓，因此会被拒绝。

### 3.2 取消、删除与修改

项目采用审计优先的不可变记录模式：

- **取消**：把成交标记为 `CANCELLED`，原因是 `CANCELLED`。
- **删除**：不是物理删除，而是软取消，原因是 `DELETED`。
- **修改**：原成交以 `AMENDED` 原因取消，再创建一条新成交；新记录通过 `supersedesTradeId` 指向原记录。

取消一笔 `BUY` 可能使后续 `SELL` 失去足够持仓，因此系统会重新验证整个时间序列。若会产生负持仓，取消或修改操作将被拒绝。

## 4. 持仓与加权平均成本

系统按 `(accountId, ticker)` 分组计算持仓，使用加权平均成本法，不支持 FIFO、LIFO 或税务批次。

### 4.1 买入

买入后：

```text
新数量     = 原数量 + 买入数量
新成本基础 = 原成本基础 + 买入数量 × 买入价格
新平均成本 = 新成本基础 ÷ 新数量
```

示例：

```text
买入 10 股，价格 $100：数量 10，成本基础 $1,000，平均成本 $100
再买  5 股，价格 $130：数量 15，成本基础 $1,650，平均成本 $110
```

平均成本不是两次成交价的简单平均；它按数量加权。

### 4.2 卖出

卖出时，成本基础按卖出前的平均成本减少：

```text
卖出前平均成本 = 原成本基础 ÷ 原数量
新数量         = 原数量 - 卖出数量
新成本基础     = 新数量 × 卖出前平均成本
```

延续上例，卖出 6 股后：

```text
剩余数量     = 15 - 6 = 9
剩余成本基础 = 9 × $110 = $990
平均成本     = $110
```

卖出价格不会改变剩余持仓的平均成本。它通常参与已实现盈亏计算，但本项目当前 **不计算已实现盈亏**。当数量归零时，该持仓不再出现在持仓列表中，成本基础重置为零。

## 5. 市场行情与缓存语义

成交价（`tradePrice`）是历史交易事实；市场价（quote price）是当前估值输入，二者用途不同。

项目支持确定性的 Mock 行情和 Finnhub 行情。行情可能带有以下状态：

| 状态 | 含义 |
| --- | --- |
| `MOCK` | 开发环境生成的确定性模拟价格，不是真实市场数据 |
| `LIVE` | 成功从外部行情提供方取得的数据 |
| `CACHED` | Redis 中仍处于有效期的缓存数据 |
| `STALE` | 实时请求失败时返回的过期兜底数据 |

Redis 不是系统的事实来源，清空 Redis 不会丢失账户、成交、持仓或估值历史。行情缺失时，API 保留 `null`，前端不会用零价格代替，以免制造虚假的巨额亏损。

## 6. 市值与未实现盈亏

对有可用行情的持仓：

```text
市值（marketValue）         = 持仓数量 × 市场价
未实现盈亏（unrealizedPnl） = 市值 - 成本基础
盈亏百分比（pnlPercent）    = 未实现盈亏 ÷ 成本基础 × 100
```

示例：持有 9 股，成本基础为 `$990`，当前市场价为 `$125`：

```text
市值       = 9 × $125 = $1,125
未实现盈亏 = $1,125 - $990 = $135
盈亏百分比 = $135 ÷ $990 × 100 ≈ 13.6364%
```

未实现盈亏表示“如果按当前价格估值”的账面变化，并不等于实际收到的现金。只有卖出后才会形成已实现盈亏，而这不在当前项目范围内。

组合汇总只累加有有效报价的持仓，同时报告已定价和未定价持仓数量。只要存在未定价持仓，汇总值就是部分估值，使用方不能把它理解为完整组合价值。

## 7. 精度、时间与一致性

### 7.1 金额精度

后端使用 Java `BigDecimal` 和 `DECIMAL128` 进行核心计算，金融小数在 JSON 中以字符串传输，避免 JavaScript IEEE-754 浮点误差。调用方不应先把金额转换为二进制浮点数再提交。

### 7.2 时间

API 时间采用 `Instant`，表达 UTC 时间点。界面可以按本地时区显示，但持久化和比较应以统一时间点为准。持仓重放依赖 `executedAt`，错误的时区转换可能改变成交先后顺序并触发负持仓校验。

### 7.3 并发一致性

交易应用服务在写入关键成交前锁定相关账户，并在同一事务中校验时间序列。修改成交若跨账户，会按 UUID 的稳定顺序锁定两个账户，以降低死锁风险。应用层校验与数据库事务共同保证“校验通过的序列”和“最终写入的序列”一致。

## 8. 估值历史

后端默认每分钟：

1. 找出所有未平仓股票代码；
2. 每个代码强制刷新一次行情；
3. 计算全账户和单账户 P&L；
4. 把 `ALL` 与 `ACCOUNT` 范围的估值快照写入 MySQL。

`1D`、`7D`、`30D` 是滚动窗口，`ALL` 返回本地已收集的全部历史。历史从后端开始采集时才存在，不会自动回填启动之前的数据。大结果会在 API 层降采样到最多 1,440 个点，但数据库仍保留全部快照。

## 9. 实现边界

阅读指标或扩展功能前，应牢记当前边界：

- 单用户，无认证和授权；
- 仅支持 USD，没有现金余额、资金冻结或多币种换汇；
- 禁止空头持仓；
- 只有未实现盈亏，没有已实现盈亏；
- 只有加权平均成本，没有 FIFO、LIFO 或 tax lot；
- 不包含订单簿、挂单、撮合、佣金、税费、公司行动、结算和对账；
- 行情采用轮询和缓存，不提供 WebSocket 实时流；
- Mock 行情仅用于开发和演示。

因此，本项目更准确地说是一个“成交记账与持仓估值引擎”，而不是完整的交易所、订单管理系统或券商后台。

## 10. 测试场景速查

| 场景 | 预期结果 |
| --- | --- |
| 活跃账户买入受支持股票 | 创建 `BOOKED` 成交并增加持仓 |
| 非活跃账户下单 | 拒绝 |
| 卖出数量大于可用持仓 | 拒绝并报告可用数量 |
| 取消会支撑后续卖出的买入 | 若时间序列变负则拒绝 |
| 修改成交 | 原记录以 `AMENDED` 取消并生成关联替代记录 |
| 删除成交 | 记录保留，状态变为 `CANCELLED/DELETED` |
| 同价不同数量的多次买入 | 按数量加权计算平均成本 |
| 行情缺失 | 该持仓标为未定价，价格和 P&L 保持 `null` |
| 行情服务故障且有旧缓存 | 可返回明确标记的 `STALE` 行情 |
| 持仓完全卖出 | 数量和成本归零，持仓不再展示 |
